# 3D hero (scholar cat)

The owner asked (2026-10-25) for a genuinely three-dimensional hero next to the 2D layered one, made by
hand in Blender (the Hyper3D trial key had no credits; this machine cannot run a local generator). The
look is a first pass: the owner will review the design later. The app still draws the 2D layers
(`lib/content/figure.ts`); nothing here is wired into the screens yet.

## Files

- `blender/cat3d.blend` — scene `CatModel`: collection `Body` (the cat, its rig `CatRig`, the sockets) and
  one collection per item, `Item <id>`. The approved 2D cat stands beside it as a hidden reference
  (`REF approved cat`, from `art/layers/cat-base.png`).
- `public/models/cat/cat.glb` — the cat: meshes skinned to `CatRig`, animations, sockets, ear morphs.
- `public/models/cat/items/<id>.glb` — one per item: its meshes skinned to a copy of the same skeleton.
  Items: `plain-tunic` (the starter clothes: tunic, collar, lacing, belt, sleeves), `violet-tunic`,
  `violet-robe`, `brown-coat`, `midnight-cloak`, `witch-hat`, `round-glasses`, `star-amulet`, `wand`.

Scale: the model is built at 1 unit = 100 px of the 2D master (feet at 0, ~8.4 units tall); the rig
object is scaled 0.1, so the GLBs are ~0.84 m tall, Y up (glTF).

## Rig

Bones: `root`, `hips` → `spine` → `chest` → `neck` → `head`; `upper_arm.L/R` → `hand.L/R` (from `chest`);
`leg.L/R` → `foot.L/R` (from `hips`); `tail.01`–`tail.04` (from `hips`). Rigid parts (head, eyes, ears,
paws, boots, hat, glasses, wand) have one bone at weight 1; garments, sleeves and the tail are weighted by
distance to their two nearest bones.

Sockets (empties parented to bones, exported as nodes): `Socket_Head` (hat), `Socket_Face` (glasses),
`Socket_Neck` (amulet), `Socket_Back`, `Socket_Body`, `Socket_HandR`, `Socket_HandL`. Every item is
already placed and skinned, so the sockets are for things added later (a companion, a held object
without a rig of its own).

Animations: `Idle` (48 frames, loops: breathing, head tilt, tail sway) and `Wave` (40 frames, the right
paw).

Morph target `Tucked` on `EarL/R`, `EarInnerL/R`: the ears pressed down. Set it to 1 while a hat is worn
(the owner's rule: a hat covers the ears).

## Equipping in three.js

Load `cat.glb` once and keep its `SkinnedMesh` skeleton. For an item, load its GLB and, for every
`SkinnedMesh` in it, bind it to the cat's skeleton by bone name:

```ts
const bones = new Map(cat.skeleton.bones.map((b) => [b.name, b]));
itemMesh.bind(
  new THREE.Skeleton(
    itemMesh.skeleton.bones.map((b) => bones.get(b.name)!),
    itemMesh.skeleton.boneInverses,
  ),
  itemMesh.bindMatrix,
);
catRoot.add(itemMesh);
```

(Checked only by importing the GLBs back into Blender, where the items sit on the cat; this three.js code
has not been run yet: the app has no 3D viewer.) Taking an item off is removing its meshes. Wearing an outfit (`violet-tunic`, `violet-robe`) replaces
`plain-tunic`; `brown-coat` and `midnight-cloak` go over it.

## Colours and size

The fur's white blaze and the tail's white tip are procedural in Blender; for glTF they are baked into a
vertex colour attribute (`Col`) on `Head` and `Tail`, and the fur materials read it. Every other
material is a plain colour, so the GLBs carry no textures. The cat is ~40 000 triangles, 1.4 MB; items
0.6–9 k triangles. Draco or meshopt compression is available in Blender's exporter if size matters.

## Known gaps (design pass pending)

- The fur is velvet (sheen and a noise bump), not plush; the bump does not survive glTF.
- Garment shells are single-sided in glTF (their lining exists only in Blender's solidify).
- The cloak and the tail pass through each other; there is no cloth simulation.
- Ears from the side are thin; the tunic is simpler than the 2D one.

## Re-export

In Blender with the MCP: open `blender/cat3d.blend`, select `CatRig` and a collection's objects, File →
Export → glTF 2.0 (.glb) with Selected Objects, Active Scene, Skinning, Shape Keys, Animation (cat only),
Custom Properties; Apply Modifiers off.
